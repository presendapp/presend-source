● Presend

डेवलपर्स के लिए Presend API

सामान्य कार्यों के लिए निःशुल्क सर्वर-साइड एंडपॉइंट्स, साथ ही एम्बेड करने योग्य क्लाइंट-साइड टूल्स। किसी API कुंजी की आवश्यकता नहीं। कोई साइनअप नहीं।

सर्वर-साइड एंडपॉइंट्स

ये Cloudflare के edge नेटवर्क पर चलते हैं और JSON लौटाते हैं। केवल फेयर-यूज़ — कोई आधिकारिक SLA नहीं, भारी या स्वचालित ट्रैफ़िक बिना सूचना के सीमित किया जा सकता है।

Python उपयोगकर्ताओं के लिए: urllib के डिफ़ॉल्ट User-Agent (Python-urllib/3.x) से भेजे गए अनुरोधों को Cloudflare HTTP 403 और बॉडी error code: 1010 के साथ अस्वीकार कर देता है। कोई भी स्पष्ट User-Agent सेट करें। requests, curl और Node ऐसा User-Agent भेजते हैं जो स्वीकार किया जाता है। 

import json, urllib.request
req = urllib.request.Request("https://presend.pages.dev/api/uuid", headers={"User-Agent": "my-app/1.0"})
print(json.load(urllib.request.urlopen(req)))

POST /api/hash

20MB तक की किसी भी फ़ाइल के लिए SHA-256, SHA-1 और SHA-512 लौटाता है।

curl -X POST --data-binary @file.pdf \
  https://presend.pages.dev/api/hash

# {"size_bytes":17,"hashes":{"sha256":"...","sha1":"...","sha512":"..."}}

POST /api/file-type

फ़ाइल के बाइनरी सिग्नेचर से उसका असली प्रकार पहचानता है और घोषित Content-Type से मेल न खाने पर चेतावनी देता है — ऐसी छद्म फ़ाइलें पकड़ता है (जैसे फ़ोटो के नाम से रखी गई executable फ़ाइल) जो साधारण अपलोड फ़िल्टर से निकल जाती हैं।

curl -X POST --data-binary @suspicious.jpg -H "Content-Type: image/jpeg" https://presend.pages.dev/api/file-type

POST /api/malware-check

अपलोड की गई फ़ाइल का हैश (SHA-256) निकालकर उसे MalwareBazaar (abuse.ch) से जाँचता है, जो ज्ञात मैलवेयर नमूनों का एक मुफ़्त डेटाबेस है — हैश और जाँच एक ही कॉल में।

curl -X POST --data-binary @file.exe https://presend.pages.dev/api/malware-check

GET /api/url-clean

किसी URL से 60+ ट्रैकिंग पैरामीटर (utm_*, fbclid, gclid...) हटाता है।

curl "https://presend.pages.dev/api/url-clean?url=https://example.com/?utm_source=x"

# {"clean":"https://example.com/","removed":1,"valid":true}

POST /api/url-clean

वही, बैच में — एक अनुरोध में अधिकतम 100 URL।

curl -X POST -H "Content-Type: application/json" \
  -d '{"urls":["https://a.com?fbclid=x","https://b.com?gclid=y"]}' \
  https://presend.pages.dev/api/url-clean

curl https://presend.pages.dev/api/ip

GET /api/uuid

रैंडम UUID (v4) बनाता है, एक अनुरोध में अधिकतम 100।

curl "https://presend.pages.dev/api/uuid?count=5"

GET /api/base64

टेक्स्ट को Base64 में एनकोड या डिकोड करता है।

curl "https://presend.pages.dev/api/base64?action=encode&text=hello"

GET /api/jwt-decode

किसी JWT के हेडर और पेलोड को डिकोड करता है (सिग्नेचर की जाँच नहीं करता; उसके लिए jwt-verify का उपयोग करें)।

curl "https://presend.pages.dev/api/jwt-decode?token=eyJhbGci..."

POST /api/jwt-verify

Workers की नेटिव Web Crypto API से JWT के क्रिप्टोग्राफ़िक सिग्नेचर (HS256/384/512, RS/PS256/384/512, ES256/384/512) की वास्तविक जाँच करता है, साथ ही exp/nbf क्लेम भी जाँचता है। HMAC के लिए “secret” दें, या असममित एल्गोरिदम के लिए “jwk”/“jwks_url”।

curl -X POST -H "Content-Type: application/json" -d '{"token":"...","secret":"..."}' https://presend.pages.dev/api/jwt-verify

GET /api/timestamp

वर्तमान समय, या Unix टाइमस्टैम्प और ISO तारीख के बीच रूपांतरण।

curl "https://presend.pages.dev/api/timestamp?unix=1700000000"

GET /api/color

hex, RGB और HSL रंग फ़ॉर्मेट के बीच रूपांतरण करता है।

curl "https://presend.pages.dev/api/color?hex=ff5733"

GET /api/user-agent

User-Agent स्ट्रिंग को ब्राउज़र, OS और डिवाइस प्रकार में पार्स करता है।

curl "https://presend.pages.dev/api/user-agent"

GET /api/password

एन्ट्रॉपी अनुमान के साथ क्रिप्टोग्राफ़िक रूप से सुरक्षित पासवर्ड बनाता है।

curl "https://presend.pages.dev/api/password?length=20&symbols=1"

GET /api/email-validate

ईमेल सिंटैक्स की जाँच करता है और देखता है कि डोमेन का MX रिकॉर्ड है या नहीं। यह मेलबॉक्स की जाँच नहीं करता, इसलिए पते के मौजूद होने की पुष्टि नहीं कर सकता; डिस्पोज़ेबल डोमेन और रोल अकाउंट भी पहचानने के लिए email-verify का उपयोग करें।

curl "https://presend.pages.dev/api/email-validate?email=foo@example.com"

GET /api/favicon

किसी भी डोमेन का favicon URL लाता है।

curl "https://presend.pages.dev/api/favicon?domain=github.com"

GET/POST /api/csv-json

JSON और CSV के बीच रूपांतरण करता है। नेस्टेड ऑब्जेक्ट स्ट्रिंग बना दिए जाते हैं, फ़्लैट नहीं किए जाते।

curl -X POST -H "Content-Type: application/json" \
  -d '{"direction":"json-to-csv","data":"[{\"a\":1}]"}' \
  https://presend.pages.dev/api/csv-json

GET /api/password-breach

जाँचता है कि कोई पासवर्ड ज्ञात डेटा उल्लंघनों में है या नहीं (Have I Been Pwned)। HIBP को उसके SHA-1 हैश के केवल पहले 5 अक्षर भेजे जाते हैं (k-anonymity), और Presend उसे लॉग नहीं करता। लेकिन यह GET अनुरोध है, इसलिए पासवर्ड URL में जाता है, जहाँ ब्राउज़र, प्रॉक्सी या सर्वर लॉग उसे दर्ज कर सकते हैं: असली पासवर्ड के लिए POST /api/password-check का उपयोग करें।

curl "https://presend.pages.dev/api/password-breach?password=..."

POST /api/password-check

एक ही कॉल में स्ट्रेंथ/एंट्रॉपी स्कोरिंग और वैकल्पिक ब्रीच जांच को जोड़ता है — पासवर्ड POST बॉडी में भेजा जाता है, कभी URL में नहीं। password-breach जैसी ही k-anonymity गारंटी।

curl -X POST -H "Content-Type: application/json" -d '{"password":"..."}' https://presend.pages.dev/api/password-check

GET /api/email-disposable

576+ ज्ञात डोमेन की सूची से डिस्पोज़ेबल/अस्थायी ईमेल प्रदाताओं का पता लगाता है।

curl "https://presend.pages.dev/api/email-disposable?email=foo@mailinator.com"

GET /api/email-verify

सिंटैक्स जांच, MX लुकअप, डिस्पोजेबल डोमेन डिटेक्शन, और जेनेरिक/रोल अकाउंट डिटेक्शन (info@, admin@...) को एक ही कॉल में जोड़ता है ।

curl "https://presend.pages.dev/api/email-verify?email=foo@example.com"

GET /api/phone-verify

libphonenumber-js के माध्यम से फोन नंबर को सत्यापित और फॉर्मेट करता है (E.164, अंतरराष्ट्रीय, राष्ट्रीय)। यदि "+" प्रीफिक्स के बिना नंबर के लिए कोई देश नहीं दिया गया है, तो कॉलर के IP से अनुमानित देश स्वचालित रूप से उपयोग किया जाता है।

curl "https://presend.pages.dev/api/phone-verify?number=%2B14155552671"

GET /api/email-security

किसी डोमेन की ईमेल स्पूफ़िंग-रोधी सेटिंग जाँचता है: SPF की मज़बूती, DMARC नीति, और सामान्य सेलेक्टर्स पर सर्वोत्तम-प्रयास DKIM खोज।

curl "https://presend.pages.dev/api/email-security?domain=example.com"

GET /api/security-scan

security-headers, url-reputation और subdomains को एक रिपोर्ट में जोड़ता है, जिसमें कुल स्कोर और निर्णय होता है — तीन की जगह एक कॉल।

curl "https://presend.pages.dev/api/security-scan?url=https://example.com"

POST /api/qr-scan

अपलोड की गई इमेज से QR कोड डिकोड करता है, और अगर वह किसी URL पर ले जाता है तो उसे URLhaus में मैलवेयर/फ़िशिंग संकेतों के लिए जाँचता है — डिकोड और प्रतिष्ठा जाँच एक ही कॉल में। QR कोड फ़िशिंग (“quishing”) सबसे तेज़ी से बढ़ते फ़िशिंग तरीकों में से एक है।

curl -X POST -F "file=@qrcode.png" https://presend.pages.dev/api/qr-scan

GET /api/security-headers

HTTP सुरक्षा हेडर (CSP, HSTS, X-Frame-Options...) का ऑडिट करता है और अक्षर ग्रेड देता है।

curl "https://presend.pages.dev/api/security-headers?url=https://example.com"

GET /api/url-reputation

किसी URL को URLhaus से जाँचता है, जो मैलवेयर/फ़िशिंग का सार्वजनिक डेटाबेस है।

curl "https://presend.pages.dev/api/url-reputation?url=https://example.com"

GET /api/subdomains

Certificate Transparency लॉग (crt.sh) के ज़रिए निष्क्रिय सबडोमेन खोज — अपनी स्वयं की अटैक सरफ़ेस के ऑडिट के लिए। ध्यान दें: यह crt.sh पर निर्भर है, जो कभी-कभी हमारे नियंत्रण से बाहर डाउन रहता है।

curl "https://presend.pages.dev/api/subdomains?domain=example.com"

GET /api/ai-crawler-check

robots.txt लाकर बताता है कि कौन-से ज्ञात AI क्रॉलर (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot आदि) अनुमत हैं या ब्लॉक हैं। मुफ़्त, साइनअप की ज़रूरत नहीं।

curl "https://presend.pages.dev/api/ai-crawler-check?domain=example.com"

GET /api/ip-reputation

किसी IPv4 या IPv6 पते को ऐसे नेटब्लॉक की चुनी हुई सूची से जाँचता है जिनके बारे में ज्ञात है कि वे हाईजैक किए गए हैं या स्पैम/साइबर-अपराध समूहों के नियंत्रण में हैं। यह एक विशेष सूची है, पूर्ण प्रतिष्ठा स्कोर नहीं। कॉपी दिन में अधिकतम एक बार रिफ़्रेश होती है; प्रतिक्रिया में सूची की तारीख, श्रेय, और एक stale फ़्लैग होता है, अगर मूल स्रोत इतनी देर तक उपलब्ध न रहा हो कि कॉपी 48 घंटे से पुरानी हो गई हो। अपने middleware में हर अनुरोध की जाँच के लिए, आम तौर पर सूची को स्थानीय रूप से लोड करना बेहतर डिज़ाइन है।

curl "https://presend.pages.dev/api/ip-reputation?ip=1.2.3.4"

GET /api/dns-lookup

Cloudflare के DNS-over-HTTPS रिज़ॉल्वर से A, AAAA, CNAME, MX, TXT और NS रिकॉर्ड एक ही कॉल में, या type= से केवल एक प्रकार।

curl "https://presend.pages.dev/api/dns-lookup?domain=example.com"

GET /api/whois-lookup

RDAP के ज़रिए रजिस्ट्रार, बनने और समाप्ति की तारीखें, डोमेन की उम्र और नेमसर्वर — RDAP पुराने WHOIS का HTTPS-आधारित उत्तराधिकारी है।

curl "https://presend.pages.dev/api/whois-lookup?domain=example.com"

GET /api/redirect-trace

किसी URL की पूरी रीडायरेक्ट श्रृंखला (अधिकतम 15 हॉप) का पालन करता है और हर हॉप का स्टेटस कोड और गंतव्य दर्ज करता है, सिर्फ़ अंतिम URL नहीं।

curl "https://presend.pages.dev/api/redirect-trace?url=http://github.com"

सप्लाई-चेन सुरक्षा

निर्भरताओं (dependencies) के जोखिम की जाँच। typosquat-check और maintainer-change-check अनुमान-आधारित (heuristic) हैं: प्राथमिकता तय करने के संकेत, निर्णय नहीं।

GET /api/typosquat-check

उन पैकेज नामों को चिह्नित करता है जो प्रसिद्ध npm और PyPI पैकेजों की चुनी हुई सूची के किसी नाम से बहुत मिलते-जुलते हैं (4–7 अक्षरों के नामों के लिए 1 बदलाव, 8+ के लिए 2; 3 या कम अक्षरों वाले नामों की अनुमानित तुलना नहीं होती)। PyPI नाम सामान्यीकृत किए जाते हैं (PEP 503); जाँचे गए वैध मिलते-जुलते नाम known_legitimate से चिह्नित होते हैं।

curl "https://presend.pages.dev/api/typosquat-check?ecosystem=npm&package=lodahs"

POST /api/typosquat-check

बैच मोड: एक अनुरोध में अधिकतम 100 नाम, जिसे रेट लिमिट में एक ही अनुरोध गिना जाता है। अमान्य प्रविष्टि केवल उसी प्रविष्टि के लिए त्रुटि लौटाती है, पूरा बैच विफल नहीं होता।

curl -X POST -H "Content-Type: application/json" -d '{"ecosystem":"npm","packages":["lodahs","expres","react"]}' https://presend.pages.dev/api/typosquat-check

GET /api/maintainer-change-check

केवल npm। पिछले 365 दिनों में, 180+ दिनों की निष्क्रियता के बाद किसी पैकेज को पहले कभी न देखे गए मानव प्रकाशक द्वारा संभालने को चिह्नित करता है: event-stream समझौते (2018) के पीछे यही पैटर्न था। ऐसे प्रकाशक को हस्तांतरण जो पहले से 1,00,000+ साप्ताहिक डाउनलोड वाला कोई दूसरा पैकेज संभालता है, और npm trusted publishing पर जाना, अलग से बताए जाते हैं और फ़्लैग नहीं उठाते। यह किसी मौजूदा मेंटेनर खाते के हाईजैक होने या मूल मेंटेनर की दुर्भावनापूर्ण रिलीज़ का पता नहीं लगाता, क्योंकि प्रकाशक की पहचान नहीं बदलती।

curl "https://presend.pages.dev/api/maintainer-change-check?ecosystem=npm&package=lodash"

POST /api/maintainer-change-check

बैच मोड: एक अनुरोध में अधिकतम 20 npm पैकेज, जिसे रेट लिमिट में एक ही अनुरोध गिना जाता है। कोई पैकेज न मिलने या रजिस्ट्री विफल होने की सूचना हर प्रविष्टि के लिए अलग दी जाती है, पूरा बैच विफल नहीं होता।

curl -X POST -H "Content-Type: application/json" -d '{"ecosystem":"npm","packages":["lodash","express"]}' https://presend.pages.dev/api/maintainer-change-check

GET /api/vulnerability-check

OSV.dev पर पैकेज संस्करण जाँचता है: npm, PyPI, Go, crates.io, Maven, RubyGems, Packagist, NuGet। किसी CVE या GHSA पहचानकर्ता को सीधे खोजने के लिए cve-lookup का उपयोग करें।

curl "https://presend.pages.dev/api/vulnerability-check?ecosystem=npm&package=lodash&version=4.17.15"

GET /api/repo-health-check

curl "https://presend.pages.dev/api/repo-health-check?repo=lodash/lodash"

GET /api/supply-chain-check

maintainer-change-check (केवल npm), vulnerability-check, typosquat-check और repo-health-check (जहाँ संभव हो, रिपॉज़िटरी रजिस्ट्री मेटाडेटा से ली जाती है) को एक ही कॉल में जोड़ता है, कुल निर्णय के साथ।

curl "https://presend.pages.dev/api/supply-chain-check?ecosystem=npm&package=lodash"

ब्लॉकचेन

Cosmos और EVM इकोसिस्टम के लिए मुफ़्त टूल। कोई साइनअप नहीं, कोई API कुंजी नहीं।

GET /api/address-risk

किसी क्रिप्टो पते को OFAC की Specially Designated Nationals (SDN) डिजिटल मुद्रा पता सूचियों में से हर एक से जाँचता है। EVM (0x...) और Bitcoin (bc1..., 1..., 3...) पते पूरी तरह शामिल हैं; अन्य चेन के पते सूचीबद्ध होने पर चिह्नित होते हैं। Cosmos SDK (bech32) पते सूचीबद्ध न होने पर sanctioned: null लौटाते हैं, क्योंकि OFAC ने Cosmos SDK चेन के लिए कोई प्रविष्टि प्रकाशित नहीं की है।

curl "https://presend.pages.dev/api/address-risk?address=0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2"

GET /api/tx-decode

किसी कच्चे, हस्ताक्षरित Cosmos SDK लेन-देन (protobuf TxRaw बाइट्स, base64) को पढ़ने योग्य JSON में डिकोड करता है -- संदेश, शुल्क, गैस, हस्ताक्षरकर्ता जानकारी, हस्ताक्षर। कोई बाहरी निर्भरता नहीं; नेस्टेड MsgExec सहित सामान्य bank/staking/gov/authz संदेश प्रकार डिकोड करता है।

curl "https://presend.pages.dev/api/tx-decode?tx=CpwBCpEBChwvY29zbW9zLmJhbmsudjFiZXRhMS5Nc2dTZW5kEnEK..."

GET /api/rpc-check

किसी Cosmos SDK चेन के सार्वजनिक CometBFT RPC एंडपॉइंट का ऑडिट करता है: नोड स्थिति, स्वास्थ्य, पीयर कनेक्टिविटी, और क्या असुरक्षित प्रशासनिक मेथड (dial_seeds, dial_peers, unsafe_flush_mempool) उजागर प्रतीत होते हैं। केवल पढ़ने के लिए -- स्वयं कभी कोई असुरक्षित मेथड नहीं चलाता।

curl "https://presend.pages.dev/api/rpc-check?url=https://cosmos-rpc.publicnode.com"

यूटिलिटीज़

छोटे, केंद्रित टूल, जहाँ तक संभव हो बिना बाहरी निर्भरता के।

GET /api/iban-validate

ISO 7064 mod-97 चेकसम और देश-विशिष्ट लंबाई जाँच से IBAN सत्यापित करता है। शुद्ध एल्गोरिदम -- कोई बाहरी डेटा स्रोत नहीं।

curl "https://presend.pages.dev/api/iban-validate?iban=DE89370400440532013000"

GET /api/vat-validate

यूरोपीय आयोग की आधिकारिक VIES सेवा से EU VAT नंबर को रीयल-टाइम में सत्यापित करता है -- मान्य होने पर पंजीकृत कंपनी का नाम और पता लौटाता है।

curl "https://presend.pages.dev/api/vat-validate?country=IE&vat=6388047V"

GET /api/link-metadata

किसी URL से Open Graph, Twitter Card और बुनियादी <head> मेटाडेटा निकालता है -- वही डेटा जिससे चैट ऐप्स लिंक प्रीव्यू कार्ड दिखाते हैं। यह favicon और रीडायरेक्ट (हर एक की जाँच के साथ) के बाद का अंतिम URL भी लौटाता है।

curl "https://presend.pages.dev/api/link-metadata?url=https://github.com/presendapp/presend-source"

GET /api/cve-lookup

OSV.dev के ज़रिए पहचानकर्ता से सीधी CVE/GHSA खोज। जब आपके पास किसी स्कैनर रिपोर्ट से पहले से पहचानकर्ता हो, तब यह vulnerability-check (जिसे पैकेज, इकोसिस्टम और संस्करण चाहिए) का पूरक है।

curl "https://presend.pages.dev/api/cve-lookup?id=CVE-2021-44228"

चेन किए गए वर्कफ़्लो

ये दो एंडपॉइंट एक ही कॉल में सर्वर-साइड पर कई ऑपरेशन को चेन करते हैं । प्रोसेसिंग स्टेटलेस है: डिस्क पर कुछ भी नहीं लिखा जाता, कुछ भी लॉग नहीं होता, रिस्पॉन्स भेजते ही फ़ाइल हटा दी जाती है।

POST /api/merge-and-compress-pdf

2 या अधिक PDF फ़ाइलों को एक दस्तावेज़ में मर्ज करता है, फिर परिणाम को कंप्रेस करता है और मेटाडेटा (शीर्षक, लेखक, निर्माता) हटाता है — दो अनुरोधों के बजाय एक ही अनुरोध में।

curl -X POST -F "files=@a.pdf" -F "files=@b.pdf" https://presend.pages.dev/api/merge-and-compress-pdf -o merged.pdf

POST /api/clean-image

सीधे बाइनरी पार्सिंग के माध्यम से JPEG से EXIF/GPS और PNG से टेक्स्ट मेटाडेटा हटाता है — पिक्सेल डेटा को कभी भी दोबारा एन्कोड नहीं किया जाता, इसलिए गुणवत्ता में कोई कमी नहीं होती (canvas-आधारित तरीकों के विपरीत, जो हमेशा दोबारा कंप्रेस करते हैं)।

curl -X POST --data-binary @photo.jpg -H "Content-Type: image/jpeg" https://presend.pages.dev/api/clean-image -o clean.jpg

POST /api/image-similarity

1 या 2 JPEG/PNG इमेज के लिए परसेप्चुअल हैश (dHash)। क्रिप्टोग्राफ़िक हैश के विपरीत, यह दोबारा कंप्रेशन और छोटे बदलावों के बाद भी टिकता है — 2 इमेज भेजकर उन्हें समानता स्कोर और निर्णय के साथ सीधे तुलना करें।

curl -X POST -F "files=@a.jpg" -F "files=@b.png" https://presend.pages.dev/api/image-similarity

POST /api/text-similarity

1 या 2 टेक्स्ट के लिए SimHash — image-similarity का टेक्स्ट संस्करण। क्रिप्टोग्राफ़िक हैश के विपरीत, यह दोबारा लिखी गई या थोड़ी बदली गई लगभग-दोहराई सामग्री पहचानता है। असंबंधित टेक्स्ट आम तौर पर संयोग से ~50% स्कोर करते हैं, 0% नहीं।

curl -X POST -H "Content-Type: application/json" -d '{"texts":["text a","text b"]}' https://presend.pages.dev/api/text-similarity

क्लाइंट-साइड टूल्स (एम्बेड)

फ़ाइल प्रोसेसिंग के ज़्यादातर टूल (EXIF हटाना, PDF कंप्रेशन, आदि) स्वतंत्र विजेट के रूप में पूरी तरह ब्राउज़र में भी चलते हैं — कुछ भी अपलोड नहीं होता। जब आपको सर्वर कॉल के बजाय तैयार इंटरफ़ेस चाहिए, तो ऊपर दिए गए API के बजाय इनका उपयोग करें। सीधे एम्बेड करें: 

<iframe 
  src="https://presend.pages.dev/tools/exif-remover?embed=1" 
  width="100%" 
  height="600" 
  frameborder="0"
></iframe>

RapidAPI

RapidAPI पर भी उपलब्ध, क्षेत्र के अनुसार अलग-अलग, अगर आपको कैटलॉग का केवल एक हिस्सा चाहिए:

  • Presend API -- पूरा कैटलॉग (Cybersecurity)
  • Presend Blockchain & Crypto Compliance API -- OFAC जाँच, Cosmos SDK लेन-देन डिकोडिंग, RPC ऑडिट (Finance)
  • Presend Email & Phone Verification API -- ईमेल और फ़ोन सत्यापन (Email)
  • Presend Developer Tools API -- UUID, Base64, टाइमस्टैम्प, IP जियोलोकेशन, PDF/इमेज टूल (Tools)
