2 in 3 agency-built Next.js sites ship a critical vulnerability

We read the Next.js version served by websites that agencies list as their own work in the DatoCMS, Storyblok and Netlify partner directories, and matched each version against the published advisories. Most of these sites were never updated after launch.

Being on 16.x is not enough: many 16.x sites run a release from before the fixes for the critical advisories published in 2026 (fixed in 16.3.3 and 16.4.1). On 15.x the same fixes landed in 15.5.24 and 15.5.28.

Whether a given site is exploitable depends on its configuration (for example, whether image optimisation is enabled and how it is hosted). We did not test any site: the figures say which sites run an affected version, not which ones can be attacked.

Why agency sites in particular

An agency builds the site, launches it, and moves on to the next project. Bots such as Dependabot open update pull requests, but someone has to read the changelog, test and deploy, and that work is rarely in anyone's contract. A major version (13 or 14 to 16) is a small project in itself, so it keeps being postponed. Meanwhile, the framework publishes critical fixes every few weeks.

Method

  • Sites: those listed by agencies as their projects in the public partner showcases of DatoCMS, Storyblok and Netlify, plus the agencies' own websites; about 1,300 addresses, collected on 19 November 2026.
  • Version: read from the public JavaScript files each homepage loads (Next.js embeds its version there). Only the homepage and those files were requested; nothing was tested.
  • Advisories: the public OSV database for the next npm package, which mirrors the GitHub Security Advisories, queried the same day.
  • Limits: about one Next.js site in five did not expose a readable version and are not counted; a site behind a CDN may serve an older build than its repository; the sample is agency work, not the whole web.
  • We contacted most of the agencies concerned privately. No site is named on this page.
